# 📱 แผนแนวคิด: พัฒนา EDcalendar รองรับการใช้งานทั้งบนคอมพิวเตอร์และมือถือ (Cross-Platform Web App)

> **สถานะ**: บันทึกแนวคิด (Idea Documentation) — ยังไม่เริ่มดำเนินการพัฒนาจริง  
> **วันที่บันทึก**: 17 กันยายน 2026  
> **โปรเจกต์**: EDcalendar (Teaching Schedule & Calendar Management)

---

## 🎯 1. วัตถุประสงค์ (Goal & Vision)

ให้คุณครูสามารถใช้งานระบบได้อย่างสะดวกและต่อเนื่องในทุกบริบทของการทำงาน:
* **บนคอมพิวเตอร์ (PC / Laptop)**: 
  * สำหรับจัดเตรียมตารางสอนช่วงเปิดภาคเรียน
  * บันทึกข้อมูลรายวิชา แผนการสอนระยะยาว
  * ดูรายงานสรุปผลภาพรวม และสั่งพิมพ์เอกสารทางการ (A4 แนวนอน)
* **บนมือถือ (Smartphone / Tablet)**:
  * พกติดตัวขณะเดินสอนในโรงเรียน
  * ตรวจสอบคาบสอนถัดไป (วิชาอะไร, ห้องไหน, ชั้นอะไร) ได้รวดเร็ว
  * บันทึกสถานะหน้าห้องได้ทันที เช่น "งดสอน", "ติดกิจกรรมโรงเรียน", "ขอสอนชดเชย"

## 🖥️📱 2. การออกแบบหน้าจอ (Responsive Web Design)

ใช้สถาปัตยกรรม **"เว็บเดียว ปรับขนาดตามอุปกรณ์อัตโนมัติ" (Single Codebase Responsive App)**:

### 2.1 มุมมองบนคอมพิวเตอร์ (Desktop Mode)
* แสดงตารางกริดมาตรฐาน 8 คาบเต็มหน้าจอ
* ปฏิทินรายเดือน 5 วันแบบตารางใหญ่
* แดชบอร์ดสรุปผลพร้อมกราฟและตารางแบบ Side-by-Side
* เมนูนำทางแบบแถบด้านบน (Header Bar)

### 2.2 มุมมองบนมือถือ (Mobile Mode)
* **แถบเมนูด้านล่าง (Bottom Navigation Bar)**: สลับระหว่าง "ตารางสอน", "ปฏิทิน", "สรุปผล" ได้สะดวกด้วยนิ้วโป้งมือเดียว
* **การ์ดตารางสอนรายวัน (Today's Schedule / Day Cards)**: หน้าแรกของมือถือแสดงวิชาที่ต้องสอนในวันนี้เป็นหลัก เรียงตามลำดับเวลา เพื่อให้ดูง่ายที่สุดโดยไม่ต้องเลื่อนหา
* **ตารางกริดแบบเลื่อนนุ่มนวล (Smooth Horizontal Scroll)**: สำหรับการดูตารางรวมทั้งสัปดาห์บนมือถือ
* **ปุ่มสัมผัสขนาดใหญ่ (Touch Targets)**: เพิ่มระยะห่างและขนาดปุ่ม ป้องกันการกดผิดช่อง

## 📲 3. สถาปัตยกรรม PWA (Progressive Web App)

เปลี่ยนเว็บไซต์ให้มีความสามารถเหมือนแอปพลิเคชันมือถือแท้ โดยไม่ต้องส่งขึ้น App Store หรือ Google Play Store:
* **ติดตั้งลงหน้าจอโฮมได้ (Add to Home Screen)**: ได้ไอคอนแอปสวยงามบนหน้าจอมือถือ
* **เปิดแบบเต็มจอ (Standalone Display)**: ไม่มีแถบ URL หรือปุ่มควบคุมของเบราว์เซอร์มากวนใจ
* **รองรับการทำงานออฟไลน์ (Offline-First via Service Worker)**: แม้ห้องเรียนจะไม่มีสัญญาณอินเทอร์เน็ต ก็ยังเปิดดูตารางสอนได้ตามปกติ

## ☁️ 4. การนำขึ้นออนไลน์และการเข้าถึง (Hosting & Deployment)

เพื่อให้เข้าใช้งานผ่าน URL เดียวกันได้ทุกที่ทุกเวลา:
* **บริการโฮสติ้งฟรี**: **Vercel** หรือ **Cloudflare Pages**
  * ผูกกับ Repository บน GitHub
  * อัปเดตโค้ดอัตโนมัติเมื่อมีการแก้ไข
  * มี HTTPS และ SSL Certificate ปลอดภัยตามมาตรฐาน
  * ได้โดเมนใช้งานฟรี เช่น `https://edcalendar-app.vercel.app`

## 🔄 5. การเชื่อมต่อและซิงค์ข้อมูลข้ามอุปกรณ์ (Data Synchronization)

เนื่องจากคอมพิวเตอร์และมือถือเป็นคนละเครื่องกัน ข้อมูลต้องเชื่อมถึงกัน:

### ทางเลือกที่ 1: ระบบล็อกอินด้วย Google (แนะนำที่สุด ⭐⭐⭐⭐⭐)
* **เทคโนโลยี**: เชื่อมต่อ Cloud Database ฟรี เช่น **Supabase** หรือ **Firebase**
* **รูปแบบการทำงาน**:
  1. มีปุ่ม "เข้าสู่ระบบด้วย Google" ทั้งบนคอมฯ และมือถือ
  2. ใช้ Gmail เดียวกันในการล็อกอิน
  3. เมื่อแก้ไขตารางสอนบนคอมฯ ข้อมูลจะวิ่งไปอัปเดตบนมือถือทันทีแบบ Real-time
  4. หากเปลี่ยนมือถือใหม่ ข้อมูลก็ไม่สูญหาย เพียงล็อกอินใหม่ก็ดึงข้อมูลเดิมกลับมาได้ทันที
* **ค่าใช้จ่าย**: ฟรี 100% (แพ็กเกจฟรีรองรับการใช้งานระดับบุคคลได้อย่างสบาย)

### ทางเลือกที่ 2: ระบบสแกน QR Code เพื่อส่งข้อมูล (ทางเลือกรอง ⭐⭐⭐)
* **รูปแบบการทำงาน**:
  1. บนคอมพิวเตอร์มีปุ่ม "ส่งข้อมูลเข้ามือถือ" แล้วสร้าง QR Code
  2. เปิดมือถือแล้วสแกน QR Code ข้อมูลจะถูกถ่ายโอนเข้ามาเก็บในเครื่องมือถือทันที
* **ข้อดี**: ไม่ต้องผูกบัญชีหรือมีระบบ Database
* **ข้อจำกัด**: ถ้ามีการแก้ไขข้อมูลในคอมฯ เพิ่มเติม ต้องคอยสแกนส่งข้อมูลใหม่เป็นระยะ

## 🛠️ 7. แผนขั้นตอนการพัฒนา (Roadmap Phasing)

* **ระยะที่ 1 (UI & Mobile Responsive)**:
  * ปรับแต่งเลย์เอาต์ CSS ให้รองรับหน้าจอมือถือ
  * เพิ่มแถบ Bottom Navigation และมุมมองการ์ดตารางสอนรายวัน
* **ระยะที่ 2 (PWA Setup)**:
  * สร้างไฟล์ `manifest.json`, Service Worker สำหรับ Cache ข้อมูล
  * จัดทำไอคอนแอป (App Icons & Splash Screens)
* **ระยะที่ 3 (Cloud Sync & Authentication)**:
  * ติดตั้ง SDK Supabase หรือ Firebase
  * ทำระบบ Login ผ่าน Google และบันทึกข้อมูลขึ้น Cloud
* **ระยะที่ 4 (Production Deployment)**:
  * Deploy ขึ้น Vercel และทดสอบการเปิดใช้งานจริงบนอุปกรณ์มือถือ
